Mobile-orch

Dual-Track Fleet Controller

Drives roughly 280 accounts across two entirely different device backends — physical Android handsets over USB, and cloud instances over REST — from one scheduler.

ResultOne operator now covers what took two, and an interrupted run resumes instead of restarting.

  • Slot-based worker pool, six concurrent jobs, each with isolated device state
  • Slot-prefixed logging ([S0], [S1]) so a failure in parallel output is traceable in seconds
  • Run state persisted per account — a crash costs one job, not the batch
  • One scheduler abstracts both backends behind a common device interface
Stack Python 3, ADB, vendor REST · Surface CLI daemon
Mobile-orch

Account Lifecycle Daemon

Runs the full lifecycle on cloud devices — provision, assign proxy, set locale, install, register, warm, retire — as one resumable pipeline.

ResultA multi-step setup that took an operator most of an hour now runs unattended.

  • ~13,000 lines in the main daemon, organised around a single base class
  • All machine-specific values isolated in one config module, never scattered inline
  • Every stage is independently re-runnable against an account mid-lifecycle
Stack Python 3 · Surface CLI daemon
Data-pipe

Account Status Scraper

Daily job that checks the standing of ~800 accounts and reconciles a master sheet against what it finds.

ResultA manual morning routine across a VA team became a job that finishes before anyone logs in.

  • Skip-list retires known-dead accounts so they stop burning requests every run
  • Separate backfill tooling repaired several months of bad historical entries
  • Writes to MongoDB as source of truth; the sheet is reconciled, never trusted
  • Runs on cron at a fixed UTC hour, with a queue consumer on a 5-minute cycle
Stack Python 3, MongoDB, Sheets API · Surface cron + CLI

How I work

  1. barebones first

    You get the smallest thing that works, then we add only what you ask for. No speculative flags, no options nobody requested, no config for a case that hasn't happened yet.

  2. session report

    Every working session ends with a written report. Grouped by area, bullet points, what changed — not how. You can forward it to someone who wasn't there.

  3. project memory

    Decisions, lessons and open tasks live in the repo. Picking the project back up after two quiet weeks costs nothing, whether it's me or the next person.

  4. inherit, don't rewrite

    Porting a working flow to a new backend means carrying the logic across. Rewrites are how you lose the nine edge cases that took a month to find.
